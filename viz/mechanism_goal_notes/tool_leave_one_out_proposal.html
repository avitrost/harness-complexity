Codex Full Tool Leave-One-Out Proposal

Approval document for a cleaner family of Codex-full ablations. Each proposed variant keeps the Codex-full harness as fixed as possible while removing one explicit model-visible tool affordance and removing matching model-visible prompt/schema references.

Proposed rule. For each tool, disable the explicit harness-provided tool call, remove direct prompt/schema mentions of that tool, but leave bash-level workarounds available where that is scientifically possible.

Important exception. exec_command is the shell access tool. Removing it does not leave a bash workaround. I propose treating it separately as either a negative control or a renamed-shell control, not as a standard leave-one-out member.

Current Codex-Full Tool Surface

Tool Current role Can function be approximated through bash? Standard leave-one-out?
apply_patch Structured file editing through a custom freeform patch grammar. Yes. Use heredocs, python - <<'PY', sed, perl, or file rewrites. yes
update_plan Structured planning state rendered outside normal assistant text. Mostly yes. The model can keep plan text in normal messages or temporary files, but loses structured status state. yes
write_stdin Continuation/polling for an existing harness-managed terminal session. Partly yes. The model can use tmux, background jobs, log files, ps, and tail via exec_command. yes
exec_command Primary shell execution channel. No. This is bash access. Removing it removes the bash workaround itself. separate control

Proposed Variants

Variant Disable Prompt/schema removal Bash fallback still allowed Hypothesis tested
codex_full_loo_apply_patch patch_tool=False; block shell-level apply_patch interception. Remove all apply_patch guidance from base instructions and do not advertise the custom patch grammar. Yes: normal shell file editing only. Whether the special structured edit affordance itself is responsible for the performance lift.
codex_full_loo_update_plan plan_tool=False. Remove the ## Planning section, direct update_plan references, and the final ## update_plan tool-instruction section. Yes: ordinary assistant text or local notes. Whether structured external planning state helps the weak model maintain task control.
codex_full_loo_write_stdin write_stdin_tool=False. Remove write_stdin tool schema and remove/rewrite model-visible session_id guidance that says to pass IDs to write_stdin. Yes: tmux, background jobs, PID/log polling, repeated shell commands. Whether harness-managed persistent terminal continuation is a key scaffold.
codex_full_no_exec_command exec_command removed. Remove shell-command guidance and tool schema. No. Negative control only. This should perform badly and is not a fair member of the bash-fallback family.
codex_full_renamed_shell Remove the exec_command name, but replace it with an equivalent bash or shell tool. Remove exec_command wording while preserving shell-use guidance under the replacement tool. Yes, by construction. Whether the Codex-native exec_command name/schema prior matters, independent of shell access.

Approval question. I recommend running the first three as the main leave-one-out set. For exec_command, I recommend codex_full_renamed_shell if you want a serious experiment, and codex_full_no_exec_command only as a sanity negative control.

Prompt Edits

apply_patch

Remove direct patch-tool guidance from the task execution and presentation sections.

Remove lines containing:
- "Use the `apply_patch` tool..."
- "Do not waste tokens by re-reading files after calling `apply_patch`..."
- "if you've created or modified files using `apply_patch`..."
- any "patches" wording that implies the custom tool

Keep general file-editing instructions. Do not forbid shell editing.

update_plan

Remove both the broad planning guidance and the dedicated tool appendix.

Remove sections:
## Planning
  ... all text through the examples block ...

## `update_plan`
  ... all text through "If all steps are complete..."

Also remove standalone references like "making & updating plans" and "plan tool".

write_stdin

There is little base-prompt text for this tool; most mentions are in the model-visible tool schema and command-output schema.

Remove from model-visible schemas:
- the `write_stdin` tool schema
- "Session identifier to pass to write_stdin..."
- output fields that only exist to route to write_stdin, unless rewritten neutrally

Preserve normal shell advice. The model can still use tmux, logs, and background jobs through exec_command.

exec_command

This needs an explicit design choice before implementation.

Option A: no exec_command
- remove shell tool entirely
- negative control, not bash-fallback comparable

Option B: renamed shell
- replace exec_command with equivalent bash/shell tool
- removes Codex-specific name/schema prior
- keeps task solvability

I recommend Option B for a useful mechanism test.

Implementation Sketch

Area Change Reason
FeatureSet Add explicit prompt-guidance booleans for plan, write_stdin, and optionally exec_command. Reuse existing patch_prompt_guidance. Keeps tool removal separate from prompt removal and lets tests assert each profile precisely.
PROFILE_OVERRIDES Add the proposed profiles with one tool affordance removed per profile. Makes the experiment grid auditable and reproducible.
Prompt filtering Replace the current patch-only filter with a section-aware filter that can remove tool-specific sections and line-level references. Avoids dangling prompt instructions for tools that are not visible.
Tool schemas Ensure removed tools do not appear in router.model_visible_specs(). For no-write-stdin, remove or neutralize session_id guidance. The model should not see an unavailable affordance.
harbor_adapter For no-apply-patch only, keep blocking shell-level apply_patch interception. Do not block ordinary shell editing. Prevents the removed custom patch tool from re-entering through exec_command.
Tests Add assertions for visible tool names, absence of removed prompt strings, and allowed bash fallbacks. Prevents contaminated ablations before running the expensive eval.

Recommended Approval Set

  1. Approve codex_full_loo_apply_patch, using the already-clean no-patch-affordance behavior as the implementation basis.
  2. Approve codex_full_loo_update_plan, removing both model-visible tool schema and planning prompt guidance.
  3. Approve codex_full_loo_write_stdin, removing the tool and dangling session_id guidance while preserving bash/tmux fallbacks.
  4. Choose whether exec_command should be excluded, included only as codex_full_renamed_shell, or included as a negative control.
